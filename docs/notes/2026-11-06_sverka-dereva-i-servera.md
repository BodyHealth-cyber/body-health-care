# Сверка: что в дереве = что на сервере (06.11.2026)

Перед правками проверили, совпадает ли рабочее дерево с тем, что отдаёт
body-health.care. Короткий ответ: **да, совпадает полностью.**

## Как устроен деплой

`.github/workflows/deploy.yml`: push в `master` → `bash build.sh` →
`wrangler pages deploy dist --project-name=body-health-care --branch=master`.
Каталог `dist/` в гите не хранится (в `.gitignore`), его собирает CI.

## Как проверяли

1. Собрали сайт ровно как CI: `git archive HEAD | tar -x` во временный
   каталог, затем `bash build.sh`. Получилось 66 HTML-страниц.
2. Скачали с живого сайта все 66 страниц плюс `css/style.css`,
   `js/main.js`, `js/quiz.js`, `robots.txt` и сравнили.

## Результат

- `css/style.css`, `js/main.js`, `js/quiz.js`, `robots.txt` — **совпали
  побайтово**. Хеши версий в ссылках (`?v=da1aaa5a6477`, `?v=7fb0c873e1f1`,
  `?v=8ca5f60a0d8f`) на живом те же, что даёт локальная сборка.
- Все **66 из 66** HTML-страниц совпали по содержимому.
- GitHub `master` = локальный HEAD = `cbc58f1` (19.09.2026).

## Две «разницы», которые разницей не являются

Поначалу 11 страниц из 22 выглядели как отличающиеся. Обе причины — не наши:

1. **Cloudflare Email Address Obfuscation включён.** На edge каждый
   `mailto:` и каждый адрес в тексте переписываются в
   `/cdn-cgi/l/email-protection#…` + `class="__cf_email__"` и рядом
   подключается `/cdn-cgi/scripts/…/email-decode.min.js`. Отсюда лишние
   ~327–426 символов на страницах с почтой. Страницы без адресов
   (`services`, `login`, блог, `for-companies`) совпали побайтово сразу.
   Практический вывод: **в исходниках почта остаётся обычным `mailto:`**,
   обфускацию делает Cloudflare, руками её повторять не нужно.
2. **`sitemap.xml`** — `generate-sitemap.py` ставит `<lastmod>` = дата
   сборки, поэтому он всегда отличается от любой прошлой сборки.

Ещё одна мелочь: внутри одного `<script>` на каждой странице есть блок
~235 символов, который меняется от запроса к запросу — это инъекция
Cloudflare, к содержимому сайта отношения не имеет.

## Почему в workflow wrangler, а не pages-action

`cloudflare/pages-action@v1` был удалён из GitHub 19.09.2026 — сборка
падала на «Unable to resolve action». Тот же деплой делает
`cloudflare/wrangler-action@v3`. Чернетка `docs/notes/deploy.yml.new`,
где это было записано комментарием, удалена: сам файл workflow трогать
нельзя — у токена нет scope `workflow`, и пуш отклоняется.
